# 项目原则

更新日期：2026-10-24。来源：当前用户对话、合并前 Calhack 文档及 cal-hack-proj 的既有原则与 ADR。本次合并只整理来源，不替两位协作者修改仓库已约定的原则或批准新功能。

## 共同产品方向

MirrorVille 是虚拟小镇，每位用户拥有 AI 分身。分身根据用户的身份、兴趣及获授权资料活动；用户回顾分身的相遇和故事，获得认识新人、维系关系和开启真人交流的话题。仓库表达为 **Your mirrors meet first. Then you do.**

## 当前对话中用户明确要求

- 登录与注册，注册收集用户名、邮箱、密码、生日。
- 注册后通过人格资料／问题与社交媒体授权，让 AI 更了解用户。
- Library 回顾自上次登录后的行动、相遇和事件，并允许添加内容指导后续行动。
- Settings 管理系统设置、人格资料及相关账号授权。
- Share 将自己的小镇分享到社交媒体。

这些要求仍保留；本次没有证据表明用户已撤回或接受仓库原型作为完整替代。细节与 FigJam 来源见 [产品流程](../design/mirrorville-product-workflow.md)。

## 仓库已记录的决定与约束

仓库 [原则原文](repository-principles.md) 写明“agreed in discussion”，ADR 0001–0008 标记 Accepted。这是从仓库导入的既有状态，不把它混写为当前对话中新增的用户确认。

- 目标是促成真人连接；分身不代替主人承诺、安排见面或与真人发言。
- 不弹窗、不催答、不设过期或拒绝按钮；连接理由需要用户资料支持。
- 导入只处理本人的文字，先在浏览器脱敏；个人卡片默认隐藏，可按房间覆盖。具体默认可见性遵循 [0005](../decisions/0005-mirror-room-privacy.md)。
- React + Vite 前端、SpacetimeDB 后端，DeepSeek 对话与 Claude 判断的分工见 [决策索引](../decisions/README.md)。代码存在不等于各模型路径均通过运行检查。
- 最新仓库目标为每次对话写日记、可见的单向兴趣、双方确认后解锁联系方式（[0008](../decisions/0008-diary-and-mutual-interest.md)）；该决定部分取代 0003，尚未实现。
- 仓库计划两人协作，演示让评委扫码创建分身；记录的 Devpost 首次提交目标为 2026-10-25 09:00 PT。这是仓库来源的排期，本次未向主办方重新核验。
- 仓库约束为活动期间自写代码、不使用 AI Town 代码；本周末不做多世界服务器、世界生成器、语音、原生应用和实时位置。不是本次对赛事规则的独立核验。

## 尚需对齐

- 邮箱注册与真实社交平台授权尚无实现证据；当前原型采用浏览器匿名身份、TIPI 和文本导入。问卷与授权的必填／任选／跳过规则仍需确认。
- 原始 Library / Settings / Share 与 Town / Postcards / Mirror Room 及日记计划如何对应，尚无完整映射或替代决定。
- 原对话中的“常驻公共小镇 + 私人小镇”仍为 Proposed；仓库当前仅 venue 真正运行，其他房间只有可见性设置。部署选择 0007 不等于房间功能已实现。
- 初始规模、预算、具体社交平台、真实 API 范围及最终产品验收边界仍需对齐。
