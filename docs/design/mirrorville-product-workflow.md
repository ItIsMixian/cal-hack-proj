# MirrorVille 产品与流程

更新日期：2026-10-24。来源：本次用户对话。本文整理需求与设计，不声称应用已经实现。

## 产品概念

用户的 AI 分身在虚拟小镇中，根据用户的身份资料、兴趣与获授权的社交媒体信息活动。分身间的相遇和故事成为真人认识、联系和维系关系的话题。

核心价值链：用户资料 → 分身互动 → 可回顾的故事 → 真人对话 → 现实关系。

## 用户明确要求的流程

### 登录与注册

- 打开应用进入 Login。
- 已有账号：输入邮箱和密码，验证失败后重试；成功进入软件主体。
- 没有账号：点击 Registration，填写用户名、邮箱、密码、生日。
- 注册后进入 “Help Your AI Get to Know You”，可填写人格资料／问题，或进行社交媒体授权。
- 用户举例包括 MBTI、星座、Aron 36 个问题；并未确定具体采用哪套问卷或全部必填。

### 主体操作

| 入口 | 用户要求 |
| --- | --- |
| Library | 回顾上次登录后分身做了什么、见了谁、发生了什么；添加内容来指定分身接下来的动作 |
| Settings | 修改系统设置、当前人格及相关账号授权 |
| Share | 将自己的小镇分享到社交媒体，扩大接触范围 |

## 助手补充的设计，尚未获用户确认

- Onboarding 至少完成一种方式即可继续；未完成者下次登录回到 Onboarding。
- Library 指令经保存后影响后续 AI 行动，新活动再进入 Library。
- Share 增加预览、平台选择、确认与取消路径。
- Settings 中的 authentication 按社交媒体授权理解；是否还包含密码、登录安全等账号设置待澄清。

服务器与小镇组织方式仍在讨论，见 [方案材料](../library/mirrorville-server-options.md)。
