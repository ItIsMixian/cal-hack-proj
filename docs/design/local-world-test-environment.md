## 使用与重启

在 `cal-hack-proj` 仓库目录执行：

```powershell
npm.cmd run setup:worlds
npm.cmd run dev
```

- 前端：`http://127.0.0.1:5173/`；选择 Explore as a guest。
- 第二个独立游客：在同一浏览器打开 `http://localhost:5173/`，其网页存储与 127.0.0.1 分开。也可使用独立浏览器配置。
- 后端：`http://127.0.0.1:3010`；健康检查 `/v1/ping`；数据库 `mirrorville-worlds-test`。
- 首次启动脚本下载官方 SpacetimeDB 2.13.0，与 SDK 版本匹配；安装锁定的后端依赖，启动隐藏后台服务，发布测试库并生成绑定。
- 后端数据、签名密钥、CLI 登录和日志都在 gitignored `.local-backend/`；前端模式配置是 gitignored `.env.worldtest.local`。保留该目录才能保留本机数据和已签发游客身份。
- `setup:worlds` 可以再次执行，使用同一数据目录和身份，明确 `--delete-data=never`；启动后端后，单独运行前端即可。当前已运行的 5173 服务无需重复启动。
- `npm.cmd run build` / `build:worlds` 构建 worldtest 模式；`npm.cmd run test:worlds:live` 对这个固定本机测试库执行合成身份测试。

版本来源：[官方 2.13.0 发布](https://github.com/clockworklabs/SpacetimeDB/releases/tag/v2.13.0)、[CLI 文档](https://spacetimedb.com/docs/cli-reference/)。

## 当前功能

- 新游客加入公共测试大厅；每人最多 5 个世界位置，包含大厅。
- 在空位创建世界；创建者拥有编辑权限，房主本身占一个人数名额。设置名称、简介、陌生人开关和最多人数（1–100）。
- Menu 分开显示 Guest session（登录方式）与 World owner／World member（当前世界权限角色），游客账号也可以是房主；localhost 与 127.0.0.1 使用不同游客身份。房主 Menu 有 Edit world 和 Copy invitation link。非房主没有这两个入口；后端仍独立验证权限。
- 邀请链接携带客户端密码学随机生成的 256-bit token，保存在私有表中，仅房主视图返回。邀请允许加入私人世界；人数满则拒绝。后端支持替换邀请以使旧链接失效。
- 空位可粘贴链接加入。加入与名额检查在 reducer 事务内完成；重复加入不重复占位。开放世界的无邀请加入接口也经过陌生人设置检查。
- Explore the public town 打开另一层公共发现列表，显示所有当前身份尚未加入、允许陌生人且成员人数未满的小镇，仅提供名称、简介和人数。加入自动使用非公共空位，后端再次检查权限／人数／分身容量，确认后才离站；已有原型自动生成独立分身。所有已加入小镇（包含默认大厅）按名称保留在主列表。加载、连接中断、无可加入小镇和个人位置已满有英文提示。[验证](../validation/2026-10-25-public-town-discovery.md)。
- 角色、对话、台词的底层表为私有，只经当前世界成员视图提供。日记同时按主人和世界过滤，旧关系记忆也按世界分开。
- 每个分身固定属于创建它的世界。切换只改变查看的世界，不移动分身、不结束原世界对话，也不清空休息状态。已有分身原型的用户首次进入新世界，会自动创建独立分身；没有原型才保留手动创建流程。不同世界拥有独立档案、联系方式、卡片、导入、日记及关系记忆。
- 每个世界有独立的移动／社交时钟、模拟随机序列与对话并发额度；所有已创建世界持续参与后台 tick，不依赖当前查看者或用户是否在线。打开空位只浏览入口窗口。相同身份的标签页仍共用服务器上的查看选择，但不会改变任何世界的居民归属。
- 浏览器旧预览世界不会自动导入到真实测试库；服务器数据决定已加入世界与房主身份，测试模式不提供伪造房主切换。

私有表与视图依据：[SpacetimeDB 访问权限](https://spacetimedb.com/docs/tables/access-permissions/)。实际检查见 [初次部署记录](../validation/2026-10-25-local-world-backend.md) 和 [独立分身修复验证](../validation/2026-10-25-independent-world-mirrors.md)。

## 边界

- 无公网地址、没有更改 OAuth 回调，也未发布 Maincloud。此次先使用独立游客身份；真实邮箱登录未在该环境配置。
- 没有复制原共享数据库、原 `.env.local`、模型密钥或业务数据。DeepSeek/Claude 密钥为空，真实 AI 模型调用未验证。不要直接用旧 `set-keys` 脚本配置此环境，它读取旧配置；模型接入须明确指向本测试库。
- 本次私有表／公开视图改动与旧共享库的 schema 不兼容；只向新测试库发布。原共享库升级需要独立迁移方案，不能通过删除原数据解决。
- 人数是身份成员数；分身上限为每人每世界 3 个、每世界 60 个，每世界最多 6 场同时对话；每日 good-fit 标记每人每世界最多 2 次，导入处理互斥也按世界计算。这些上限，不代表已经验证 100 人同时模拟。暂无退出世界、转让房主和删除世界界面。
- 自由探索的随机分配 UI、邀请有效期、持续后台自动启动、性能压测、跨设备登录和真实模型行为仍待后续工作。
- 本轮测试产生了明确命名的 QA 合成世界／分身；浏览器有 Local Test World（房主与受邀者各一个身份）。集成测试会增加合成数据，不宜无限重复运行。

## 2026-10-25 独立分身升级

用户明确要求各世界中的分身与内部运行互相独立，取代初版“切换会移动分身”的行为。新增私有 `world_simulation` 表，保留旧 `world_runtime` 作为兼容存储，发布使用 `--delete-data=never`。已有分身保留在升级时所属的世界；无法恢复初版没有保存的历史副本。后续新增的分身按下方原型规则自动创建。

逻辑隔离在同一 SpacetimeDB 进程和测试数据库内实现，共用机器与模型配置，不是每个世界单独部署服务。服务器关闭时模拟停止；当前没有停服期间的离线追赶。模型密钥仍为空，因此这里只验证移动、模拟调度与隔离，真实 AI 内容生成尚未验证。

## 2026-10-25 进入世界自动创建分身

用户进一步明确：用户记录已有 AI 分身原型时，进入新世界应自动生成该世界的分身。新增私有 `mirror_prototype`（身份主键），保存姓名、外观、人格 selfCard、外向程度与初始意向。新用户首次手动创建时保存原型；已有用户在需要时从自己的非 demo 分身补建，多个候选用最小 ID 确定稳定来源（不声称 ID 顺序代表创建时间）。

创建世界、邀请加入、开放加入及切换已有世界都调用同一事务内的进入逻辑。目标世界已有自己的分身时保留原记录，包括管理员停用的记录；否则有原型才创建一个，使用新 ID、新出生位置与独立运行状态。无原型用户仍完成创建问卷。容量满则拒绝自动创建／进入，不能绕过成员权限、人数或分身容量限制。空世界入口尚未创建／加入世界时不会生成分身。

原型保存的是基础设定快照，世界中的后续修改不回写它。联系方式、导入卡片、摘要、日记、关系、对话及行为进度不随原型复制；目前没有编辑原型的独立界面。本次同样用 `--delete-data=never` 新增表升级；[验证](../validation/2026-10-25-auto-world-mirrors.md)。
