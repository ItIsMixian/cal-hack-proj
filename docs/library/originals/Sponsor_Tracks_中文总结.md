## 1. 整体要点

- 主办方鼓励至少参加一个赞助商赛道；赞助商也可能直接从参赛学生中招聘。
- 多个赛道强调：赞助商技术必须对产品有实质贡献，并能在运行中的演示里证明，简单附加一个功能通常不够。
- 常见评审重点包括真实用户需求、创新性、技术实现、端到端可用性，以及隐私、安全和负责任的设计。
- 若干赛道明确偏好范围小但可用的产品，而不是只存在于幻灯片中的宏大设想。
- 截图没有说明跨赛道重复参赛或同时获奖的通用规则，不能据此判断奖项能否叠加。

### 奖励口径中容易混淆的地方

- **CREAO 的 $5,000 是三个赛道共享的总现金奖池**，不能按每个赛道各 $5,000 计算。
- **Coinbase 的最高 $4,000 是两个赛道合计上限**；截图写的是按队员、按赛道发放的 USDC，并非每队固定 $4,000。

- **Apify 的五名奖励合计 $5,000**；截图另外列出 Best Actor 的 $400，但没有进一步说明它与总奖池的核算关系。
- Meta 的第二轮邀请附有资格和官方规则审核条件；不能理解为无条件晋级。

## 3. 已展示的详细要求与评分标准

### 3.1 Notability：展示完整的思考与构建过程

评审关注四项：

1. **过程**：笔记能否呈现想法从第一张草图到最终产品的演进。
2. **细节**：笔记是否清晰、充分，让其他人能够理解你的思考。
3. **功能使用**：是否充分使用手写、音频、图表、PDF、Smart Notes 等功能。
4. **相关性**：Notability 是否在构建过程中发挥真实作用，而不是完成后补上的材料。

### 3.2 Meta：用 AI 增强人与人的连接

评审关注项目对人际连接的实际促进程度、AI 是否必要且整合充分、原创性，以及可运行演示的质量。

### 3.3 Capital One Nessie

截图仅列出三项标准：**完整性、创造力、复杂度**，没有进一步权重或提交说明。

### 3.4 Factory Droid SDK：Agent 必须真正参与产品运行

**资格与材料**：

- 必须有意义地使用 Droid SDK，语言可为 TypeScript 或 Python。
- Droid 应在运行中的产品里完成实际工作，仅用它辅助编写代码不满足截图描述。
- 仓库 README 应说明 Droid 在哪里、如何被使用。

**高分特征**：

- 由团队设计的触发机制驱动，例如事件、定时任务、用户操作或另一个 Agent。
- 对 Droid 可以接触和操作的范围有审慎控制，并内置安全措施。
- 能看见其工作过程：计划、步骤、差异和结果。

**低分特征**：附加 Droid 的简单聊天包装、仅在幻灯片里成立的演示、无法判断 Agent 实际做了什么的项目。

### 3.5 CREAO AI：三个赛道及共享权益

三个赛道分别为 **AI-First Disruptor、One-Person Company、Team Empowerment**。后两项的标准栏均写“同上”，指向第一项的外部文档；截图没有提供具体评审标准，不宜仅凭名称补写规则。

每个获胜团队均获邀加入 **CREAO Launchpad**，权益包括：

- 1 年 CREAO Pro Max，标注价值 $1,440。
- 产品、技术及创始人方向指导。
- CREAO 交流活动、演示机会、发布支持及宣传推广。
- 与 CREAO 的职业／面试机会。

### 3.6 CRS：金融智能、Agent、身份与反欺诈

**基本要求**：有意义地使用 CRS sandbox，并在演示中展示其真实运行。

**四项评审标准**：

1. CRS 数据是否是产品核心，而非附加功能。
2. 是否能实时连接 sandbox 运行演示。
3. 是否解决个人或企业的真实问题。
4. 是否具有让评委意外的创意。

| 子奖项 | 目标 | 奖励 |
| --- | --- | --- |
| Best Overall CRS Hack | 基于 CRS 构建的最出色产品 | $1,000／队 |
| Best Financial AI Agent | 使用 CRS API 或 MCP server，让 Agent 完成实际工作 | $500／队 |
| Best Identity / Fraud Innovation | 保护消费者或企业免受欺诈与身份盗用 | 每位队员获得 CRS 开放的 Forward-Deployed Engineer 岗位面试机会 |
| Most Unexpected Use of CRS | 出人意料的 CRS 使用方式 | 每位队员获得同类岗位面试机会 |

入门资源：[CRS Cal Hacks sandbox](https://calhacks.crscreditapi.com)，包含 sandbox keys、文档及测试身份。**原文要求只使用提供的测试身份。** 问题可到 CRS 展位咨询；获胜团队将通过 Cal Hacks 与 CRS 对接。

### 3.7 Hyphenate：可承担真实岗位工作的金融自主系统

每个提交项目都按以下四个问题评估：

1. **足够真实吗？** 使用贴近现实的数据，面对复杂问题，并能证明系统有效。
2. **你会雇用它吗？** 它能承担什么岗位？是否有受限权限、清晰工作记录，并知道何时请求帮助。
3. **有新东西吗？** 是否让此前少见的公司类型、问题或处理方式实现自主化。
4. **关键时刻是什么？** 展示它发现他人遗漏、从故障中恢复，或在被质疑时解释决策的时刻。

**需要准备**：

- 以“关键时刻”开场的演示视频。
- 评审时的现场演示；评委可能要求运行其自拟场景。
- 一句话说明系统能够承担哪些岗位。
- 有效性证据，清楚区分真实部分与模拟部分，并说明验证方法。

原文另附 `CalHacks_Hyphenate_Track` 文档链接，截图没有展示其完整地址或正文。

### 3.8 Cartesia：语音是核心体验

构建有用的语音产品；可以使用其他工具，但必须说明 Cartesia 的具体贡献。

**提交内容**：

- 可运行演示。
- 2 分钟、以演示为主的展示：先呈现一个完整用户流程，再简述问题和实现方法。
- 简短 README：安装与运行方式、使用的 Cartesia 功能、已知限制。
- 按活动规则向评委提供源码访问；仓库中不得包含 API keys 或其他 secrets。

**评分：四项各占 25%**。

| 项目 | 关注点 |
| --- | --- |
| 问题与原创性 | 是否有用、范围清晰、设计经过思考 |
| Cartesia 使用 | 是否融入核心体验，语音是否清晰、响应及时、自然 |
| 执行质量 | 主要流程是否可用，是否处理常见边界情况 |
| 影响与责任 | 是否考虑无障碍、隐私和负责任使用 |

原文更偏好完成度高的可运行原型。示例方向包括：可打断的通勤晨间简报、环境／可穿戴助手、保留本人声音的无障碍朗读或跨语言表达、低延迟教练或翻译、多角色语音 Agent。

资源：[Cartesia 文档](https://docs.cartesia.ai)、[Playground](https://play.cartesia.ai)。

### 3.10 Moss：三个示例方向

2. **Personal Agent**：记住用户、跨应用工作、自主处理日常任务的个人 Agent。
3. **Social Post**：社交帖子互动表现最佳。

### 3.11 SpaceXAI：真实太空数据 + Cursor + Grok

- 原文强调利用真实太空数据、公开大型数据集、历史任务及相关文献构建项目。

评审关注：**客户理解、可衡量的实用性、从原型到生产的路径、负责任的设计、端到端功能**。

### 3.17 Spacetime：核心实时后端与共享状态

期待 Spacetime／SpacetimeDB 成为产品的核心实时后端，尤其适合实时共享状态、多用户互动，以及用户、Agent 或系统之间的即时同步。

原文提到实时订阅、事务性更新、靠近数据运行的服务端逻辑，并列举适合的方向：

- 聊天／社区、协作工具、社交体验。
- AI Agent 协调、实时仪表盘。
- 交易／金融类应用、拍卖／市场。
- 共享模拟、多人生产力工具、直播／创作者工具。

具体构想包括实时投资组合模拟、预测市场、协作交易游戏、共享运营看板、多用户规划，以及在持久共享世界状态中协作的 AI 系统。关键是 **SpacetimeDB 有实质作用**。

截图列出的参考项目有 BitCraft Online／BitCraftPublic、Elegon、Pogly，以及官方聊天应用教程／模板；这些是示例，不是必做项目。
