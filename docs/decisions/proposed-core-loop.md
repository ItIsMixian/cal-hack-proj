# Proposed: name the core feature in the principles

Status: Proposed (2026-10-24). Changes `docs/core/principles.md` on this branch; needs both teammates.

## Context

After 0008 the demo loop in the principles still described postcards and an in-app chat, and nothing
said which feature everything else serves. Discussion settled on one core loop.

## Proposal

State the premise first: people must feel their mirror is them, continuing their real life.
Without it the core loop does not work, so it is written as an assumption to test, with how to test it.
The first source of it is the owner's own words: a questionnaire alone cannot make a mirror recognizable,
so importing must be the main way in, fast on a phone (added after the owner tested cards built from
their own AI chats and WeChat messages and found them accurate; every card they recognized came from
an import, none from the personality check).


Add a "core feature" section: the mirror does the first encounter, writes it in its diary, and the
owner decides whether to pick it up (meet → diary → mutual interest → contact). Make the priority test
explicit, mark the Mirror Room and the town rhythm as supporting, everything else optional. Update the
demo loop and the no-pressure invariant to the diary model (0008), and soften the evidence invariant to
"a good fit needs a grounded reason" while 0004's exact-phrase rule is under review.

## Alternatives

Keep principles unchanged and rely on 0008: leaves the principles contradicting an accepted decision.

## If accepted

Merge this branch's principles change to `main`, then rename this file to the next decision number.
