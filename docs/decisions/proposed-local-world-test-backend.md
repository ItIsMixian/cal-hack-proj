# 独立本机多世界测试后端

Status: Proposed (2026-10-25). Implementation: deployed and tested locally, not a team consensus ADR.

用户明确要求：为当前世界 UI 部署配套后端，并选择本机独立测试环境。之前的纯前端预览范围在此被扩展为真实测试库，不等于批准公开部署或升级原共享数据库。

本次试验采用同一 SpacetimeDB 模块承载世界／身份成员／邀请／当前世界；私有底表通过成员视图提供数据，名额和房主权限由 reducer 事务校验。初版选择“一个身份选中一个活动世界，分身移动而非复制”；该实现选择已被用户后续明确的独立世界需求取代，见下方修订。测试环境仍未作为双方共识替代原则里的周末范围约束。

理由：复用现有模拟、个人档案和客户端；可以用独立身份验证权限与邀请，避免复制已有共享数据。每个世界独立数据库与跨世界记忆继承仍是未采纳的替代方案。

代价：新私有表／公开视图 schema 不兼容旧共享库；后续迁移要单独设计。测试环境使用独立端口、数据和密钥，只有本机访问，不包含模型密钥。

事实与限制见 [环境说明](../design/local-world-test-environment.md)、[实际验证](../validation/2026-10-25-local-world-backend.md)。

## 2026-10-25 用户需求修订：分身与运行独立

用户明确指出切换世界导致原世界分身消失，并要求不同世界拥有独立分身、互不影响且各自在内部持续运行。实现改为分身固定归属创建世界；查看选择不再改变居民数据。档案、联系方式、导入、日记与关系经各自分身 ID 分隔；创建、并发、每日标记和导入互斥额度按世界计算。每世界模拟时钟和确定性随机序列独立，后台遍历所有世界，无查看者也运行。

新世界创建自己的分身，不自动复制旧档案；已有记录保留当前归属。采用新增表的兼容升级，不清空测试库。共用进程和物理资源，未承诺进程或故障隔离。该用户明确需求与本机实现不等于团队已接受新的周末范围 ADR；本文保持 Proposed。[验证](../validation/2026-10-25-independent-world-mirrors.md)。

## 2026-10-25 用户后续修订：从原型自动创建

用户明确要求已有 AI 分身原型时，在进入新世界自动生成新的分身，替代上一轮“每个新世界手动创建”的交互。实现新增按身份保存的基础设定快照：姓名、外观、人格、外向程度和初始意向。旧用户没有原型表记录时，从自己的非 demo 分身按最小 ID 选择稳定来源；非时间排序。新用户仍先完成一次手动创建。

统一进入 reducer 自动确保每个世界至少已有一个自己的分身，重复进入复用同一记录；新建／邀请／开放加入均复用此流程，事务内遵守权限和容量。原型不含世界经历与私有联系人／导入资料，不自动同步各世界后续编辑；本次未增加原型编辑 UI。这些基础字段的选取是实现默认值，不扩大为跨世界记忆继承。[验证](../validation/2026-10-25-auto-world-mirrors.md)。
